# MuJoCo 纯物理乒乓球设计

## 目标

让 MuJoCo 完全通过接触动力学计算桌面反弹和球拍击球。规划器仍可预测击球并生成策略观测，但任何 Python 代码都不得为了制造反弹或击球效果而覆写仿真球的位置、线速度或角速度。

## 范围

- 删除两套脚本机制：
  - 解析式桌面反弹；
  - 解析式球拍击球。
- 初期保持当前 50 Hz 策略循环和 5 ms MuJoCo 子步长不变。
- 保留规划器、轨迹预测器、状态估计器、指令生命周期和真机后端。
- 保持当前球的质量和半径不变。
- 使用 MuJoCo 显式接触对，让球只与预期的乒乓球设施发生碰撞。

## 非目标

- 不修改 ONNX 策略或 105 维观测布局。
- 不增加 action gating。
- 不改变真机控制行为。
- 在完成多速度标定之前，不声称初始接触参数与真实球桌完全一致。
- 不允许重新加入任何把规划出球速度直接写入仿真球状态的兜底逻辑。

## 当前问题

`deploy/simulator/mujoco.py` 当前会在 `mj_step()` 之后执行两种状态覆写：

1. 球到达桌面高度时，代码会钳制球的 `z` 坐标、缩放水平速度并反转竖直速度。
2. 球靠近规划击球点时，即使没有发生真实球拍接触，代码也可能把球吸附到目标点，并把球速替换成规划器给出的期望出球速度。

XML 中已经存在可工作的球拍—球显式接触对。桌面—球接触则同时被接触排除项和球的零碰撞掩码关闭。

## 选定方案

### 运行时数据流

MuJoCo 低层循环调整为：

```text
策略 q_des
  -> PD 力矩
  -> 力矩限幅
  -> mujoco.mj_step()
  -> 读取球的位置和速度
```

物理步之后不再修改球状态。规划器只提供建议：

```text
球状态 -> 预测器/规划器 -> 策略观测 -> 策略动作
```

规划结果不得再作为强制球速回写 MuJoCo。

### Python 与配置清理

- 从 `deploy/config/hitter.yaml` 删除 `use_analytic_table_bounce` 和 `use_analytic_racket_hit`。
- 删除只用于解析式球拍击球几何体查找、且不再有其他消费者的配置字段。
- 删除 `HitterEnv._copy_hitter_command()` 中规划器到仿真器的解析式击球调用。
- 从 `deploy/simulator/mujoco.py` 删除解析式桌面反弹和球拍击球相关的状态、布防逻辑、距离判断、状态覆写函数、重置钩子和物理步后调用。
- 保留估计器的反弹检测和规划器的反弹预测，因为它们只观察或预测运动，不修改 MuJoCo 状态。

### MuJoCo 接触设计

- 保留现有 `right_racket_face_collision` 与 `hitter_ball_geom` 的显式接触对。
- 删除桌体与球之间的接触排除项。
- 增加 `hitter_table_top` 与 `hitter_ball_geom` 的显式接触对。
- 增加 `hitter_table_net` 与 `hitter_ball_geom` 的显式接触对。
- 继续关闭球的通用碰撞掩码，避免球意外撞上所有机器人网格、桌腿或装饰几何体。
- 将凸起的桌面中心白线设置为仅显示、不参与碰撞，避免它形成 6 mm 的虚假物理凸棱。

第一版保持 5 ms 子步长。现有检查表明，相对速度为 2～6 m/s 时球拍物理接触可以正常触发。如果目标工作速度范围内仍出现漏碰，再单独把 MuJoCo 子步长降低到 2 ms，同时保持策略周期为 50 Hz。

### 接触参数标定

物理接触响应由 XML 中的 `solref`、`solimp` 和摩擦参数决定，而不是规划器的恢复系数字段。初始参数首先要保证真实、稳定的反弹，然后使用多组向下和斜向入射速度进行评估。

标定输出至少包含：

- 接触前、接触后的速度；
- 实测竖直恢复系数；
- 实测水平速度保持比例；
- 是否检测到真实接触；
- 是否出现数值稳定性警告。

首次删除脚本逻辑时，不要求接触参数立刻与配置中的真机系数完全一致。但完成多速度标定之前，不得把结果描述为与真机物理等价。

### 空气模型

MuJoCo 模型启用内置流体力，使用静止标准空气的全局参数：

- `wind="0 0 0"`；
- `density="1.225"` kg/m³；
- `viscosity="0.000018"` Pa·s。

重力显式保持为 `gravity="0 0 -9.81"`。运行时仍由 `Mujoco._load_asset()` 把积分步长设置为控制配置中的 `low_dt=0.005 s`，本次不改变控制频率、发球初值、接触参数或规划器参数。由于 MuJoCo 的 `density` 和 `viscosity` 是模型级参数，流体力也会作用于其他运动刚体；乒乓球因质量很小而最明显，后续需要通过实测轨迹单独标定仿真空气参数与规划器 `drag_coefficient` 的一致性。

## 测试

实现遵循测试先行：

1. 配置测试：当前 HITTER 配置中不再启用或保留解析式反弹/击球选项。
2. 源码路径回归测试：规划指令生效时，不得调用已删除的解析式击球接口，也不得覆写球状态。
3. XML 接触测试：球拍—球、桌面—球、球网—球显式接触对存在；桌面—球排除项不存在；中心线不参与碰撞。
4. 动态桌面测试：下落球必须产生真实桌面接触，随后竖直速度变为正值，而且过程中没有 Python 状态覆写。
5. 动态球拍测试：在 2～6 m/s 工作速度范围内向球拍发射球，必须产生真实接触，并由物理解算器改变球速。
6. 稳定性冒烟测试：代表性的发球、桌面反弹和球拍接触过程保持有限数值，且不产生 MuJoCo 数值不稳定警告。
7. 空气配置测试：编译后的模型必须包含指定的重力、无风、空气密度和黏度；无接触飞行时，启用空气的球必须比关闭空气的对照球更明显地减速。

测试放入一个新的、聚焦纯物理接触的测试文件。不得恢复用户已经删除的旧测试文件，也不得改动无关的脏工作区内容。

## 预期行为变化

MuJoCo 将暴露真实的击球失败。此前解析式逻辑会把距离规划点 8 cm 内、且球拍距离球 20 cm 内的情况视为成功；改成纯物理后，这些情况中没有实际接触的都会成为真实 miss。

因此初期看到击球成功率下降是正常现象。这个下降能够真实反映策略时序、球拍姿态、碰撞几何体或接触参数存在的问题。

## 完成标准

- 不存在通过修改球位置或速度来实现桌面反弹或球拍击球的活动代码路径。
- 组合后的 HITTER 配置中不存在解析式桌面反弹或球拍击球配置。
- 桌面和球拍接触完全由 MuJoCo 生成，并有自动化测试覆盖。
- 代表性运动在当前 5 ms 子步长下保持数值稳定。
- 所有无关的工作区修改保持原样。
